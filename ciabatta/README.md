# Калькулятор чиабатты — как пользоваться на телефоне

Калькулятор рецепта чиабатты: целые граммы под нужный вес теста, пекарские
проценты, температура воды и почасовой план замеса. Один HTML-файл, без сервера
и без интернета.

## Что в папке

| Файл | Зачем |
|---|---|
| `ciabatta.html` | сам калькулятор — это единственный обязательный файл |
| `index.html` | короткий редирект на калькулятор (чтобы работал адрес папки) |
| `manifest.json` | описание приложения: имя, иконки, запуск без браузерных панелей |
| `sw.js` | офлайн-кэш: после первого открытия работает без интернета |
| `icons/` | иконки приложения (рисуются скриптом `tools/make-icons.py`) |
| `serve-lan.js`, `serve-lan.ps1` | раздают папку по Wi-Fi, чтобы открыть калькулятор на телефоне |
| `test-*.js` | автотесты: расчёт, страница, упаковка |

---

## Вариант 1. Закладка в браузере — проще всего, ничего не нужно

1. Перенесите `ciabatta.html` на телефон: отправьте себе в Telegram «Избранное»,
   положите на Google Диск или скиньте по USB в папку `Download`.
2. Откройте файл в Chrome: «Файлы» → «Загрузки» → `ciabatta.html` → «Открыть с
   помощью Chrome». Либо наберите в адресной строке `file:///sdcard/Download/ciabatta.html`.
3. Меню Chrome (⋮) → «Добавить на главный экран».

Работает офлайн, интернет не нужен. Настройки калькулятор старается сохранять;
если браузер запретит хранилище для локальных файлов, страница просто откроется
с настройками по умолчанию — сам расчёт от этого не зависит.

## Вариант 2. Иконка-приложение (PWA) — нужен любой HTTPS-хостинг

Полноценное приложение: своя иконка, запуск без адресной строки, офлайн-режим.

**Способ А — GitHub Pages (ничего устанавливать не нужно, сайт публичный по умолчанию)**

1. Откройте <https://github.com/new>. Repository name: `ciabatta`, тип **Public** →
   **Create repository**.
2. На странице пустого репозитория нажмите ссылку **uploading an existing file**.
3. Перетащите в окно браузера **всю папку с проектом** целиком, дождитесь
   загрузки → **Commit changes**. Файл `ciabatta-site.zip` можно не загружать.
4. **Settings** → **Pages** → Source: **Deploy from a branch** → Branch: **main**,
   папка **/ (root)** → **Save**.
5. Через минуту сайт будет здесь (ЛОГИН — ваш ник на GitHub):

   ```
   https://ЛОГИН.github.io/ciabatta/ciabatta.html
   ```

6. Откройте ссылку на телефоне в Chrome → меню ⋮ → **«Установить приложение»**.

Все пути внутри приложения относительные, поэтому работа из подпапки
`/ciabatta/` проверена тестом — настраивать ничего не нужно.

Необязательно: чтобы работал и короткий адрес без повторения имени папки, создайте
в корне репозитория файл `index.html` (**Add file** → **Create new file**) с
редиректом на `./ciabatta/ciabatta.html`.

**Способ Б — Netlify Drop**

1. Откройте <https://app.netlify.com/drop> и перетащите папку `ciabatta` целиком
   в окно браузера. Через полминуты появится ссылка вида
   `https://имя-123.netlify.app` (имя можно поменять в настройках сайта).
2. Откройте ссылку на телефоне в Chrome → меню ⋮ → **«Установить приложение»**
   (может называться «Добавить на главный экран»).
3. На главном экране появится иконка «Чиабатта». Она открывается на весь экран
   и работает без интернета — страница и иконки кладутся в кэш при первом запуске.

   Но сначала проверьте, что сайт не закрыт защитой доступа — см. ниже.

Важно: Chrome разрешает установку приложения только по HTTPS. Раздача по Wi-Fi
из последнего раздела для установки не подойдёт — только для проверки.

### Готовый архив для загрузки

`ciabatta-site.zip` (пересобрать: `pwsh -File tools\make-zip.ps1`) — только файлы
сайта, без тестов и служебных скриптов. Его можно перетащить на Netlify Drop или
загрузить в Cloudflare Pages (Create → Pages → Upload assets).

### Проверка, что сайт открыт для всех

```
curl -I https://ваш-адрес/ciabatta.html
```

Должно быть `200 OK`. Если `401` и в теле `Login Redirect` — сайт закрыт защитой
доступа (Netlify: Site configuration → Access & security; проверьте также SSO в
настройках команды). Telegram такую страницу показать не сможет: он получает
форму входа вместо калькулятора.

## Вариант 3. Telegram: мини-приложение внутри бота (свой сервер не нужен)

1. В Telegram напишите **@BotFather** → `/newbot` → задайте имя и юзернейм.
2. Возьмите HTTPS-ссылку из варианта 2 и в BotFather выполните `/mybots` →
   выберите бота → **Bot Settings** → **Configure Mini App** → **Enable Mini App**
   → вставьте ссылку.
3. В профиле бота появится кнопка **«Открыть приложение»** — калькулятор
   запустится прямо внутри Telegram, на весь экран.

Такой бот ничего не считает на сервере: вся математика внутри самой страницы, а
Telegram только открывает её. Поэтому компьютер держать включённым не нужно.

### Если Telegram открывает «Netlify SSO Redirect Page — Error: Invalid Path»

В адресе видно `/#tgWebAppData=user=...` — это нормально, Telegram всегда
дописывает свои данные в конец ссылки. Ошибка не в них, а в самой ссылке.

Причина: в BotFather вставлен адрес **панели** Netlify (`app.netlify.com/...`),
а не адрес опубликованного сайта. Панель требует входа в аккаунт, поэтому
Telegram вместо калькулятора получает страницу логина Netlify, а та ругается на
незнакомый путь и хвост с данными Telegram.

Как починить:

1. Откройте свой сайт в обычном браузере и скопируйте адрес из адресной строки.
   Он должен выглядеть так: `https://имя-сайта.netlify.app/` — и сразу показывать
   калькулятор, без входа в аккаунт.
2. BotFather → `/mybots` → ваш бот → **Bot Settings** → **Configure Mini App** →
   **Edit Mini App URL** → вставьте этот адрес (можно сразу с `/ciabatta.html`).
3. Полностью закройте чат с ботом в Telegram и откройте заново — мини-приложение
   кэшируется, старая ссылка может остаться.

Проверка за 10 секунд: если тот же адрес в обычном браузере (не в Telegram)
показывает форму входа Netlify — дело не в Telegram, а в сайте: он закрыт
защитой доступа. Тогда либо снимите защиту в панели Netlify, либо опубликуйте
папку на GitHub Pages / Cloudflare Pages и возьмите адрес оттуда.

### Если в Telegram страница не влезает в экран и её приходится двигать

Мини-приложения требуют жёстко зафиксированного масштаба. Без этого WebView
разрешает зум, и страница остаётся увеличенной после случайного жеста или тапа
по полю ввода — приходится возить её пальцем. Поэтому viewport выглядит так:

```html
<meta name="viewport" content="width=device-width, initial-scale=1,
      maximum-scale=1, user-scalable=no">
```

`minimum-scale` и `viewport-fit=cover` здесь намеренно НЕ указаны: первый
запрещает WebView ужать страницу, если она оказалась шире экрана (тогда правый
край просто обрезается), второй уводит содержимое под вырез экрана.

Второй источник обрезки — таблицы. У колонки с подсказками («задано 75 % ·
42,2 % от веса теста») стоял `white-space:nowrap`, из-за чего длинная строка не
переносилась и распирала страницу шире экрана. Теперь подсказки помечены классом
`note` и переносятся, а `#recipeTables`, `#waterBox` и `#plan` получили
`overflow-x:auto` — если таблица всё же окажется шире, она прокрутится внутри
себя, а не обрежется.

Дополнительно от горизонтального выезда страхуют `overflow-x:hidden`,
`min-width:0` у колонок формы и `touch-action:manipulation` (снимает зум двойным
тапом). А если Telegram сообщит WebView ширину больше 880 px, включится класс
`html.tg` (ставится по `platform` = `android`/`ios`) — он принудительно оставляет
одну колонку и показывает липкую строку с итогом.

Внутри Telegram внизу страницы видна служебная строка вида
`v6 · ширина 412 · видно 412 · масштаб 1 · TG 412×843 · dpr 2.6 · android` —
но только если в адресе есть `?debug`. Номер сборки показывает, свежая ли версия
открыта (Telegram и GitHub Pages любят отдавать страницу из кэша), `ширина` и
`видно` — совпадают ли страница и экран. Если что-то выходит за правый край,
строка начинается со слова `ВЫЛЕЗАЕТ` и называет элемент.

Автоподгонка работает всегда: если видимая область заметно уже страницы, страница
ужимается сама. Когда диагностика не нужна совсем — уберите `<div id="diag">`
и блок `wantDiag` из `ciabatta.html`.

## Проверка на телефоне по Wi-Fi (без хостинга)

1. На компьютере двойной щелчок по **`serve-lan.cmd`** (или в консоли
   `serve-lan.cmd 8080`, или `node serve-lan.js 8080`, если Node установлен).
2. Скрипт напечатает адрес вида `http://192.168.1.42:8080/ciabatta.html`.
3. Откройте этот адрес на телефоне в той же сети Wi-Fi.

Минус: работает, только пока компьютер включён и сервер запущен.

Если страница не открывается — Windows блокирует входящие соединения: разрешите
`node.exe` в брандмауэре для «Частной сети» (нужны права администратора).

### Почему .cmd, а не .ps1 напрямую

На этой машине политика выполнения скриптов — **Restricted**, поэтому `.ps1`
файлы не запускаются двойным щелчком и падают с ошибкой «выполнение сценариев
отключено». Обёртки `.cmd` запускают их с ключом `-ExecutionPolicy Bypass`, не
меняя настройки системы. Если предпочитаете вручную:

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\serve-lan.ps1
```

## Обновление установленного приложения

Если правите файлы, поднимите версию кэша в `sw.js` (`ciabatta-v6` → `ciabatta-v7`)
и залейте заново. Иначе уже установленное приложение может показывать старую
версию из кэша.

### Обновление опубликованного сайта

1. Репозиторий → **Add file** → **Upload files** → перетащите папку заново →
   **Commit changes** (одноимённые файлы перезапишутся).
2. **Подождите до 10 минут.** GitHub Pages отдаёт страницы с `Cache-Control:
   max-age=600`, и Telegram добавляет свой кэш — сразу после загрузки вы почти
   наверняка увидите старую версию. Это самая частая причина «правки не
   сработали»: сначала долго ищем ошибку в коде, которой нет.
3. Если ждать не хочется — добавьте к адресу в BotFather `?v=7` (любое новое
   число). Новый адрес обходит оба кэша сразу.

## Почему manifest.json, а не manifest.webmanifest

У GitHub Pages нет `.webmanifest` в таблице типов — файл ушёл бы как
`application/octet-stream`, и Chrome отклонил бы манифест: приложение не
установилось бы. У `.json` тип `application/json` гарантирован на любом
хостинге, и Chrome его принимает.

## Сборка архива для хостинга

```
tools\make-zip.cmd             # пересобрать ciabatta-site.zip
```

Скрипт собирает архив через .NET, а не через `Compress-Archive`: тот записывает
пути с обратными слэшами (`icons\icon-192.png`), и на Linux-хостинге вместо
папки `icons` появляется файл со «страшным» именем — иконки не находятся.
Тест `test-pwa.js` это проверяет.
